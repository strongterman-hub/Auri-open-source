# 自部署与维护

## 最小部署形态

推荐先使用一个 Python 进程和一个持久数据目录，由 Nginx/Caddy 提供 HTTPS。当前架构不支持简单增加 uvicorn worker 或复制容器来横向扩容：调度器、部分进程内状态、JSON 文件和跨模块一致性仍需进一步设计。

依次完成：本地 Echo → 真实模型 → Android 连通 → 邮件/通知 → 健康/主动 → 可选支付。不要将 `.env.example` 的开发配置原样暴露为公众服务。

## Linux 示例

下面使用 `/opt/auri` 作为示例路径，不对应官方服务器：

```bash
git clone https://github.com/strongterman-hub/Auri-open-source.git /opt/auri
cd /opt/auri/server
python3.12 -m venv .venv
.venv/bin/python -m pip install -e .
cp .env.example .env
```

创建专用服务账号并使其能读取源码、运行虚拟环境、读写数据目录。不要使用 root 运行应用。编辑 `.env`：真实模型、生产环境、自己的邮件和后台凭据、持久加密密钥、限定 CORS 等；只有配置并验收完的能力才开启。

可参考 [`server/deploy/auri.service.example`](../server/deploy/auri.service.example)。安装服务前修改路径和用户，使用 `systemd-analyze verify` 检查，然后启动并访问本机 `/v1/health`。

Nginx 反代示例见 [`server/deploy/nginx.conf.example`](../server/deploy/nginx.conf.example)。证书由你管理；示例只提供本机反代片段，不能当成完整 TLS 配置。保留适当请求体上限、读取超时与 `proxy_buffering off`，支持兼容 SSE 接口。代理层须覆盖而非信任外部传入的客户端 IP 头。

## 数据备份

备份对象是整个 `AURI_DATA_DIR`、私有配置和独立保存的加密/签名密钥。敏感备份需加密和限制读取，并与源码分开保管。

为了让多个 JSON、SQLite/WAL 和附件目录在同一时间点保持一致，简单部署可在维护窗口停止应用后整体备份，再重启。线上热备份需使用各数据库支持的备份方式并协调跨模块状态，不能只复制单个 `.db` 就假定所有关联数据一致。

定期在隔离目录做恢复测试，确认账号、会话、记忆、日程、健康、账本和小米凭据可恢复。备份不要上传到 GitHub。

## 更新与回滚

1. 阅读版本变更和迁移说明，保存当前 commit 与配置。
2. 备份数据，在副本上运行测试和必要迁移。
3. 部署相互兼容的服务端与 Android 版本。
4. 重启后检查健康、鉴权、聊天、后台任务；按启用能力检查通知和支付。
5. 回滚前评估新版本是否修改数据格式；代码回退不一定能读取迁移后的数据。

Android 直装发布需要自己的签名与版本号。先上传 APK 并核对大小/哈希，再发布元数据。不要使用官方包签名、推送或支付配置。

## 外部服务及运营

数据库可能包含聊天、健康、位置、账号和账单信息。自部署者负责访问控制、保留期限、用户删除流程、模型服务商数据处理约定及准确的隐私说明。

AI 输出需要内容处理与投诉渠道；小米实验接口需要确认实际使用权限；商店发行需遵守目标商店规则。香港或其他地区托管、源码公开，都不能直接当作面向目标用户提供服务的全部合规依据。

## 官网模板

仓库包含官方官网的页面源文件和已公开截图。独立部署时应替换品牌/运营者说明、隐私链接及下载二维码，并只发布自己构建的 APK。模板中的官方域名和二维码用于展示原项目，不代表 fork 与官方共用账号、安装包或支付服务。
