# 产品设计与能力详解

## 产品目标

Auri 探索一个长期存在于手机聊天窗口中的个人 Agent：用户不必每次重新介绍自己，也不必每句话都是指令。它保留处理任务的能力，同时通过记忆和合适的主动联系建立连续体验。

“主动找你，慢慢懂你”是一种设计目标，不是对每次模型输出的保证。Auri 是 AI，应保留明确标识，不宣称它具有人的感情或替代现实关系。

## 核心体验

### 一个连续会话

聊天历史持续存在，输入框支持连续发送；服务端先确认接受消息，生成期间顶部显示输入状态，完整回复一次出现。自然结束的短句可以不继续回复，明确问题和任务则有保护规则。

### 被记住的具体事情

长期笔记记录稳定偏好，事件时间线保存有时间、状态和来源的事情。再次提及时，Auri 应接得上话；用户纠正时，旧信息应被替代，而不是与新答案混用。事件记忆仍会有提取错误，用户纠正和可复现测试是重要反馈来源。

### 有依据的主动联系

主动内容可以来自之前的对话、未完成的事情、健康变化、天气或用户兴趣。它需要考虑用户当地时间和是否适合打扰。用户不回纯分享，不等于拒绝交流；用户没有看到通知，更不能直接等同于“关系变差”。

服务端全局主动调度与每用户主动开关分离。用户可开关主动联系，也可以用自然语言调整节奏。引导流程会说明主动调用可能产生 Credits 消耗。

### 健康作为可选情境

绑定小米后，用户可查看活动、心率、睡眠和运动数据，也可以在聊天中要求同步并询问趋势。健康源缺失时，聊天仍可继续。支持的数据类型不代表每种设备都能提供，睡眠评分不代表医疗结论。

### 日常任务与工具

支持网页查询、天气、地点、计算、单位和日期、待办、定时及健康条件提醒。位置来自用户授权设备或明确标注的回退来源。工具执行失败应表现为不可用，不应编造成功。

图片交给视觉模型，文件按类型提取文本；不能保证扫描 PDF、任意复杂表格或特殊编码文件完整解析。

## 账号与 Credits

邮箱作为账号键，支持验证码注册、找回和修改密码。密码哈希和 token 摘要在服务端保存；跨模块注销由账号删除服务编排。

Credits 是实例内部用量账本。默认配置为新用户 500 Credits、充值每元 95 Credits、按项目计价成本每元 100 Credits 扣减。此口径是已有产品实现，不是建议所有部署者采用的商业定价。

后台判断、记忆提取、摘要等也可能调用模型。运营者应明确告知费用范围，审计实际供应商账单并控制预算。自部署默认关闭扣费和支付宝，不要求读者先接支付才能运行聊天。

## 反馈原则

讨论功能时优先给出：实际场景、用户预期、现有行为、影响及可复现方式。对主动消息，请区分服务器生成、推送接受、系统展示、客户端曝光与用户回复，避免用一个“发送成功”掩盖整条链路。
